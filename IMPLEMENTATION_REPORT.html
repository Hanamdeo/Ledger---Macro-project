1. Executive Summary & Milestone Objective

The Ledger Personal Finance Analytics and Expense Management System converts the project's requirement analysis and architectural design into a fully functional, production-ready software system. The solution ingests fragmented and cryptic transaction streams (bank statement PDFs, UPI CSV exports, and e-commerce sheets), cleans and normalizes merchant narratives via a rule-based engine, stores records in an ACID-compliant local SQLite database, and presents multi-dimensional financial insights through responsive, dynamic Chart.js visualizations.

2. Deliverable 1: Source Code (Module-Wise Architecture)

The codebase is constructed with strict modularity, clean separation of concerns, and automated tests:

3. Deliverable 2: Front-End and Back-End Integration

The system establishes robust synchronization between data parsing and interactive visual analytics:

  • Dynamic Chart Visualizations (Chart.js):
    • Category Spending Breakdown (Donut Chart): Proportional allocation across 9 essential categories.
    • Monthly Inflow vs Outflow (Grouped Bar Chart): Side-by-side comparison of debit spend vs credit income.
    • Cumulative Spend & Balance Trend (Multi-Line Chart): Real-time trajectory of cash reserves and expenditure velocity.
    • Monthly Expense Distribution (Bar Chart): Aggregate debit sums grouped by calendar period.
    • Top Category Ranking (Horizontal Bar Chart): Ranked expense prioritization.
  • Interactive Merchant Normalization Sandbox: Users can enter raw, messy bank statement narrations (e.g. UPI/SWIGGY-REST4892-BLR) and inspect live regex-cleaned merchant names (SWIGGY) and automated category classifications (Food & Dining).
  • 1-Click Sample Data Injector: Enables evaluators to instantaneously populate fresh financial records with a single click, triggering real-time chart animations, recalculation of financial KPIs, and balance updates.
  • Multi-Format Data Portability: Filtered records can be exported directly to CSV, JSON, and complete SQLite SQL scripts.

4. Deliverable 3: Database Implementation (SQLite)

The persistence layer is implemented in SQLite (finance.db) adhering to 3NF relational modeling:

CREATE TABLE IF NOT EXISTS transactions (
    transaction_id TEXT PRIMARY KEY,
    date TEXT NOT NULL,
    raw_description TEXT NOT NULL,
    description TEXT NOT NULL,
    category TEXT NOT NULL,
    debit REAL DEFAULT 0.0,
    credit REAL DEFAULT 0.0,
    balance REAL NOT NULL,
    source_file TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS categories (
    category_id INTEGER PRIMARY KEY AUTOINCREMENT,
    category_name TEXT UNIQUE NOT NULL,
    color_hex TEXT DEFAULT '#64748b'
);

CREATE TABLE IF NOT EXISTS normalization_rules (
    rule_id INTEGER PRIMARY KEY AUTOINCREMENT,
    pattern TEXT NOT NULL,
    pattern_type TEXT DEFAULT 'contains',
    clean_merchant TEXT NOT NULL,
    category_id INTEGER
);
