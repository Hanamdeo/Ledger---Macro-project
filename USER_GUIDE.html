Project Overview

Ledger is a browser-based personal finance analytics application that helps users track, categorize, and visualize their income and expenses. It runs entirely in the browser — no installation required — and optionally syncs data to the cloud using Supabase.

The core innovation is its three-tier AI categorization engine: when a user adds a transaction such as "Diet Coke" or "Tata Sky", the app automatically determines the correct spending category — Food & Dining, Subscriptions & Entertainment, and so on — by querying Google Gemini, falling back to OpenAI GPT-4o-mini, and finally to a built-in 300+ keyword offline engine that works without any internet or API key.

Getting Started

Option A — Open Directly (Recommended)

  1. Download or clone the project folder to your computer.
  2. Double-click index.html to open it in your browser. No server needed.
  3. On the login screen, click "Continue as Demo" to start immediately with sample data. No account required.

Option B — Local Server (for PDF import)

The PDF import feature requires a server due to browser security restrictions on local file reading.

  1. Install Node.js (nodejs.org) if not already installed.
  2. Open a terminal in the project folder and run:
    node server.js
  3. Open http://localhost:3000 in your browser.
💡
Demo Mode — everything works in demo mode. Transactions are saved to your browser's localStorage and persist across sessions. Use a real account (Sign Up) only if you want cloud sync across devices.

AI Categorization Engine

The AI engine lives in supabase-config.js and operates as a three-tier fallback chain. This ensures categorization always works — even without internet or API keys.

The Three-Tier Chain

🤖 Tier 1: Google Gemini
gemini-2.5-flash / 2.0-flash
→
Queries the Gemini API with a strict prompt: "Return ONLY one category from [list]". Fastest and most accurate when available. Requires a free Gemini API key from aistudio.google.com.
↓ if Gemini unavailable (403 / 404 / network error)
🧠 Tier 2: OpenAI GPT-4o-mini
gpt-4o-mini
→
Falls back to OpenAI. Uses a system prompt that constrains output to the 12 exact category names. Requires an OpenAI API key with credits.
↓ if OpenAI unavailable (no key / exhausted credits)
🧠 Tier 3: In-Browser ML Classifier
MultinomialNB + Subword N-Grams
→
A statistical Machine Learning model trained on 2,280+ transactions across all 12 categories. Delivers 97.4% test accuracy, sub-millisecond client execution, confidence scoring, and online learning that adapts to user confirmations. Zero API costs, works 100% offline.

How the AI Prompt Works

The system prompt sent to Gemini and OpenAI is strictly constrained:

// System prompt (same for both Gemini and OpenAI)
"You are a personal-finance transaction categorizer.
Return ONLY one category from this exact list:
[Food & Dining, Shopping, Travel & Transport,
 Utilities & Bills, Education & Learning,
 Subscriptions & Entertainment, Health & Wellness,
 Groceries, Investments, Income,
 Personal & Transfers, Miscellaneous].
Return nothing else."

// User message
"Transaction description: "Diet Coke""

// AI responds with exactly:
"Food & Dining"

The response is then passed through normalizeCategory() which maps any slight variation (e.g. lowercase, extra words) back to the exact category key used in the app.

5.1 In-Browser Machine Learning Subsystem

To eliminate reliance on paid cloud credits and guarantee privacy, Ledger includes a fully trained Multinomial Naive Bayes + Subword N-Gram TF-IDF Classifier that runs directly inside the client's browser:

  • Dataset: 2,288 labeled financial transactions (UPI, POS, card clearing, and merchant items).
  • Accuracy: 97.38% test accuracy evaluated on an independent 458-sample holdout set.
  • Subword N-Gram Tokenization: Extracts 3-character and 4-character subwords, making the model resilient to typos, abbreviations, and messy bank statement text.
  • Confidence Scoring: Computes softmax probability distributions across all 12 categories, shown live in the Add Transaction modal (e.g., Food & Dining (99% ML)).
  • Continuous Online Learning: When you manually confirm or categorize transactions, local Bayesian priors update in localStorage, tailoring predictions to your unique spending habits.

Cloud Sync with Supabase

When a user creates an account and signs in, Ledger syncs all transactions to a Supabase PostgreSQL database. This provides:

  • Access your transactions from any browser / device
  • Real-time updates (Supabase Realtime WebSocket subscription)
  • Row-level security — each user sees only their own data

How Sync Works

  1. User signs up / signs in → cloudSignUp() / cloudSignIn() authenticate via Supabase Auth.
  2. On login, cloudFetchTransactions() pulls all saved transactions from the transactions table filtered by user_id.
  3. Every time a transaction is added or edited, cloudSaveTransactions() upserts the updated array to Supabase. Before saving, any "Miscellaneous" item is re-sent through the AI engine for a final classification attempt.
  4. Supabase Realtime pushes changes from other devices back to the open session automatically.
⚠️
Demo Mode Note — In demo mode, all data lives in localStorage only. Clearing browser data will erase transactions. Use Sign Up for persistent cloud storage.

Supabase Schema (simplified)

CREATE TABLE transactions (
  id          TEXT PRIMARY KEY,
  user_id     UUID REFERENCES auth.users,
  date        DATE,
  description TEXT,
  amount      NUMERIC,
  type        TEXT,        -- 'credit' | 'debit'
  category    TEXT,
  raw_description TEXT
);

Rules Engine

The Rules Engine lets you teach the app to recognize your personal merchants. Rules run before the AI engine — if a rule matches, the category is assigned instantly without any API call.

Rule Types

TypeHow it MatchesExample
ExactDescription must exactly equal the pattern (case-insensitive)Pattern: AMAZON PAY → Category: Shopping
ContainsDescription must contain the pattern anywherePattern: swiggy → Category: Food & Dining
RegexFull JavaScript regular expression matchPattern: ^UPI/.*@paytm → Category: Personal & Transfers

Adding a Rule

  1. Go to the Rules tab in the app.
  2. Click "+ Add Rule".
  3. Enter the Pattern (merchant name or regex), select the Rule Type, and pick the Category.
  4. Optionally set a Clean Merchant Name — this is the display name shown in the table instead of the raw bank text.
  5. Click Save. The rule is immediately applied to all existing transactions.
💡
Rules are evaluated in order, top to bottom. Drag to reorder them if two rules might conflict. The first matching rule wins.

PDF & CSV Import

Ledger can parse bank statements directly from PDF or CSV files, automatically extracting transactions without manual entry.

Importing a CSV Bank Statement

  1. Download your statement as CSV from your bank's portal.
  2. Click "Import" (or the upload icon) in the toolbar.
  3. Select your CSV file. The parser auto-detects HDFC, ICICI, SBI, and generic formats.
  4. Review the preview — each row shows the parsed date, description, and amount.
  5. Click Confirm Import. All transactions are saved and AI-categorized.

Importing a PDF Bank Statement

  1. Run the local server (node server.js) — PDF reading requires server mode.
  2. Click "Import PDF". Select your PDF file.
  3. For password-protected PDFs, enter the password when prompted.
  4. The parser extracts transaction rows, cleans merchant names, and passes them through the Rules Engine and AI categorizer.

How AI Categorization Works with Uploaded PDFs

When you upload a digital PDF statement or CSV:

  • Step 1 — Extraction: Transactions are parsed using OCR/stream matching (extracting Date, Narration, Debit, Credit, and Balance).
  • Step 2 — Narration Cleaning: Raw bank prefixes like UPI/, POS/, ACH/, and transaction reference numbers are stripped to identify clean merchant names.
  • Step 3 — Rules Engine & Smart Offline AI: Each row is checked against user rules and the built-in 300+ brand dictionary (Swiggy, Uber, Tata Sky, Decathlon, Apollo Pharmacy, etc.) for instant, zero-latency categorization.
  • Step 4 — Background AI Batch Pass: For any remaining unclassified transaction, the app automatically triggers the Gemini / OpenAI cloud engine in the background to ensure comprehensive classification.
💡
You can also click "✨ AI Auto-Categorize" on the transactions table toolbar or inside the ⚡ API Credits side panel at any time to re-classify unassigned rows.

Setting Up API Keys

API keys are stored in supabase-config.js. This file is excluded from Git (.gitignore) to prevent accidental credential exposure.

9.1 Google Gemini API Key (Recommended — Free)

  1. Go to aistudio.google.com/app/apikey and sign in with your personal Google account (not a Google Cloud project account).
  2. Click "Create API Key" → copy the key.
  3. Open supabase-config.js and paste it:
    geminiKey: "AIza...your-key-here..."
💡
The free tier at aistudio.google.com gives you 1,500 requests/day at no cost — more than enough for personal use. If your key returns a 403 error, it was created inside a Google Cloud project with billing required; create a new key from AI Studio instead.

9.2 OpenAI API Key (Optional — Paid)

  1. Go to platform.openai.com/api-keys and create a key.
  2. Add credits to your account (minimum \$5 recommended).
  3. In supabase-config.js:
    openaiKey: "sk-proj-...your-key-here..."

9.3 Supabase Keys (For Cloud Sync)

  1. Create a free project at supabase.com.
  2. Go to Project Settings → API and copy the Project URL and anon (public) key.
  3. Run the SQL in supabase_schema.sql in the Supabase SQL Editor to create tables and policies.
  4. In supabase-config.js:
    url: "https://xxxxx.supabase.co",
anonKey: "eyJhbGciO..."
🔐
Never commit API keys to Git. The supabase-config.js file is already in .gitignore. Never remove it from there or paste keys directly into app.js or index.html.

9.4 Floating Side Popup — Real-Time API Credit & Health Checker

A floating pill labeled ⚡ API Credits appears in the bottom-right corner of the application on every page:

  • Clicking it opens a slide-out side panel showing live quota, credits, and operational status for Gemini, OpenAI, and the Offline engine.
  • Click "🔍 Live Check API Credits Now" to probe all endpoints in real time. It tests your keys, detects exhausted OpenAI quotas ($0.00 left), verifies Gemini free tier access, and shows total session requests made.

Troubleshooting

ProblemLikely CauseFix
Everything shows as "Miscellaneous" No API keys set, and description isn't in keyword list Add a Gemini key (free), or add a Rule for the merchant, or click "✨ AI Auto-Categorize" after setting the key
Gemini returns 403 error Key was created in a Google Cloud project, not AI Studio Create a new key at aistudio.google.com with your personal Gmail
OpenAI returns "credit_balance_exhausted" Zero credits remaining on your OpenAI account Add credits at platform.openai.com, or use the Gemini key instead (free)
PDF import not working Opening index.html directly (file://) — browser blocks file reads Run node server.js and open localhost:3000
Data lost after clearing browser Using Demo Mode — data is in localStorage only Create an account (Sign Up) to sync to Supabase cloud
Sign in fails with "Invalid credentials" Wrong email/password or Supabase not configured Check supabase-config.js has the correct URL and anon key
Old Miscellaneous transactions not updating AI only runs on new entries by default Click "✨ AI Auto-Categorize" in the transactions toolbar to re-run on all existing ones
App shows blank page JavaScript error on load Open browser DevTools (F12) → Console tab. Check for errors. Most common: missing supabase-config.js file.

Running Without Any API Keys

The app is fully functional without any API keys. The offline fallbackSmartCategorize() engine handles categorization using pattern matching. The only features that degrade are:

  • Very unusual merchant names may fall through to "Miscellaneous" (fix: add a Rule)
  • Cloud sync is unavailable (fix: add Supabase keys)
